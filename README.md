# GaitLab

**Grades treadmill running form from a side-view phone video.** Pose keypoints become per-stride biomechanics: cadence, overstride, shin and knee angle at landing, bounce and trunk lean. A small fine-tuned LLM turns those into a 1–5 grade, issue tags and one coaching cue. A rule-based verifier checks that every cue points at a measured problem. Every number below is generated from `results/` by the evaluation scripts.

> Status: in development. Single runner, single rater, 2D side view. See [Limitations](#limitations).

## How it works

```
video ─► pose (MediaPipe | RTMPose) ─► clean + filter ─► contacts ─► per-stride features ─► 20-stride windows
                                                                                                 │
                     grade from logits + tags + cue ◄── Gemma 3 (1B | 270M) + LoRA ◄── prompt ◄──┘
                                    └─► cue verifier ─► coach app
```

- **Measurements are deterministic.** The LLM never sees raw keypoints, only per-window feature summaries ([ADR-0001](docs/adr/0001-features-not-keypoints.md)).
- **The grade is read from next-token probabilities** over "1"–"5": no parse failures, calibratable, and one static forward pass ([ADR-0002](docs/adr/0002-grade-from-logits.md)).
- **TensorRT** compiles that scoring pass; the speedup is reported only when TensorRT and eager grades match on every test prompt ([ADR-0004](docs/adr/0004-tensorrt-placement.md)).
- **Evaluation is split by session** and bootstrapped by session ([ADR-0003](docs/adr/0003-session-level-split.md)). Model agreement is reported next to my own re-grade agreement, which is the ceiling.

## Setup

Linux or WSL2 with an NVIDIA GPU for pose-on-GPU, training and benchmarks; everything else runs on CPU.

```bash
uv sync --extra video --extra mediapipe --extra ml --extra viz --extra app --extra dev
# GPU stages: install torch for your CUDA first (https://pytorch.org/get-started/locally/), then
uv sync --extra llm --extra trt --extra rtm
bash scripts/download_models.sh        # MediaPipe pose_landmarker_heavy.task
uv run pytest -m "not gpu and not data"
```

Gemma weights need the Gemma license accepted on Hugging Face and `HF_TOKEN` set for the first download. They are cached in the repo under `.hf_cache/` (git-ignored) unless `HF_HOME` is set. The `llm` extra also runs on a Mac (MPS or CPU, float32) for synthetic dry runs.

## Usage

```bash
gaitlab extract --session 20261105-01 --backend mediapipe
gaitlab process --session 20261105-01
gaitlab overlay --clip data/interim/20261105-01/natural.mediapipe.npz --video data/raw/20261105-01/natural.mp4 --gif
gaitlab label                      # labeling app; --blind 40 for the re-grade
gaitlab build-sft && gaitlab train --model 1b && gaitlab predict --model 1b
gaitlab eval && gaitlab bench --trt && gaitlab report
```

No video yet? Dry-run the chain on synthetic keypoints (all outputs flagged synthetic, never reported):

```bash
gaitlab synth --n-sessions 6 --write-keypoints
gaitlab process --session 20260101-01 --sessions data/synthetic/sessions.csv --backend synthetic
gaitlab overlay --clip data/synthetic/interim/20260101-01/natural.synthetic.npz --gif
gaitlab baselines --synthetic && gaitlab build-sft --synthetic
gaitlab train --model 270m --sft-dir data/synthetic/sft --allow-synthetic --max-steps 20
gaitlab predict --synthetic --model 270m && gaitlab eval --synthetic
```

## Data

Your own recordings plus public datasets you download under their own terms: BioCV for contact and angle validation, the Running Injury Clinic and Fukuchi 2017 datasets for norms and projected-mocap checks. Capture protocol and layout: [docs/DATA.md](docs/DATA.md).

## Limitations

- One runner and one rater. The grader is personal, not general.
- 2D side view: no frontal-plane metrics; far-side limbs are low-confidence.
- No claims about injury risk or ground-reaction loading rates.
